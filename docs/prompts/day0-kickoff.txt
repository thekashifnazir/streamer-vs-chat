We're building "Streamer vs Chat" for the Codex x TwitchCon Hackathon (deadline Mon 2 Nov 2026, 14:00 PT). The streamer survives on webcam: Twitch chat is the boss's brain and the streamer's body is the defence. Every 2.4 s beat chat votes the boss's attack: !jab / !hookl / !hookr / !combo (one vote per viewer per beat, latest wins), and !super when the hype meter is full. A "HANDS UP!" telegraph shows for 0.8 s, then the attack lands unless the streamer's pose (MediaPipe Pose Landmarker lite, in a normal Chrome page) defends it: a held guard blocks !jab and !combo, and leaning away dodges a hook. A clean block or dodge opens a short counter window that damages the boss. Punches are bonus damage only, because rule-based punch detection was unreliable on unseen people (recall 0.33-0.55 in a spike) while guard and lean read well. The keyboard (J punch, hold K guard, hold A/D lean) is a first-class input, not just a fallback. The HUD is the "Rails" layout in docs/HUD.md ("Recommended layout (B)" section) and docs/hud-rails.png: streamer rail left, boss rail right, centre kept clear for the body; it runs as an OBS browser-source overlay. Round results post to chat.

Stack: Node 22 + TypeScript, npm workspaces, @twurple/auth (RefreshingAuthProvider, Authorization Code, http://localhost:3000/callback), @twurple/api, @twurple/eventsub-ws, Vite overlay + capture page, ws for server<->overlay, vitest. Ports: the server (auth callback + ws) on 3000; Vite dev on 5173 serving /overlay (the 1920x1080 OBS browser source) and /capture. Two Twitch tokens, both stored by the server in a gitignored tokens file: the bot account (user:read:chat user:write:chat user:bot) reads and sends chat; the broadcaster account (channel:bot clips:edit, plus bits:read channel:read:subscriptions for the day-4 stretch) does the rest. Day 1 subscribes to channel.chat.message only; channel.cheer / channel.subscribe / channel.raid come on day 4.

Constraints:
- All game state lives on the server. The overlay and the capture page are views and inputs.
- Tests never call real Twitch. Use the Twitch CLI mock (`twitch event websocket start-server`). It can't mock channel.chat.message, so write a small shim that proxies the mock WS and injects EventSub-shaped chat notifications via POST /inject. Trigger other mock events with `twitch event trigger <event> -T websocket --session <id> -u <subscription id>` (twurple's `getCliTestCommand()`); a plain `trigger --transport=websocket` invents a subscription id and twurple drops it. The CLI mock listens on 8080 and the shim on 8081, so point the listener at the shim (`url: ws://127.0.0.1:8081/ws` + `TWURPLE_MOCK_API_PORT=8081`), never straight at 8080, or injected chat never arrives.
- Measured on Kash's Mac: real chat reaches the server in p50 218 ms / p95 291 ms, so the 0.8 s telegraph stays. Polls, Predictions and Channel Points are not available on this account: chat commands only.
- Never send scripted chat to a live channel. Label simulated footage on screen.
- Ship a no-login demo mode: keyboard (or webcam) as the streamer, simulated chat as the boss.
- Secrets in .env, never committed.

The exact rules, numbers, event types and acceptance tests are in SPEC.md (copied from the prep repo's docs/spec.md); treat it as the source of truth.
